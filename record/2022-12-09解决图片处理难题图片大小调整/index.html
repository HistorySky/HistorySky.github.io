解决图片处理难题：从 FFmpeg 依赖困境到 Java AWT 的优雅转身

在日常开发中，图片尺寸调整是一个常见需求。近期在项目中尝试使用 FFmpeg 处理图片缩放时，遭遇了一系列棘手的依赖问题，最终通过 Java 原生 AWT 库成功解决。本文将详细记录整个问题排查与解决方案，希望能为遇到类似问题的开发者提供参考。​

问题背景​

项目需要实现图片尺寸调整功能，最初选择使用 FFmpeg 来完成这项工作。FFmpeg 作为强大的音视频处理工具，理论上能高效处理图片缩放，但实际部署时却遇到了意想不到的麻烦。​ 最初实现的代码如下：

public static String modifyResolution(  
        String imagePath, String outputDir, Integer width, Integer height) throws Exception {  
    List<String> paths = Splitter.on(".").splitToList(imagePath);  
    String ext = paths.get(paths.size() - 1);  
    if (!Arrays.asList("jpg", "png").contains(ext)) {  
        throw new Exception("format error");  
    }  
    String resultPath =  Joiner.on(File.separator).join(Arrays.asList(outputDir, IdUtil.simpleUUID() + "." + ext));  
    String ffmpeg = Loader.load(org.bytedeco.ffmpeg.ffmpeg.class);  
    ProcessBuilder builder =  
            new ProcessBuilder(  
                    ffmpeg,  
                    "-i",  
                    imagePath,  
                    "-vf",  
                    MessageFormat.format("scale={0}:{1}", String.valueOf(width), String.valueOf(height)),  
                    resultPath);  
    builder.inheritIO().start().waitFor();  
    return resultPath;  
}

经过排查分析，发现问题根源在于 FFmpeg 的部分依赖库托管在外网服务器。在编译libxcb.so.1等依赖时，由于网络环境限制导致下载超时，最终编译失败，从而引发了后续一系列错误。​ 虽然可以通过配置网络代理或手动安装依赖库来解决，但考虑到项目部署环境的复杂性和一致性要求，这些方案的维护成本较高。因此，决定换一种更简单可靠的方式来实现图片缩放功能。

解决方案：使用 Java AWT 实现图片缩放

Java 的 AWT（Abstract Window Toolkit）库中包含了图像处理的相关类，可以直接用于图片尺寸调整，无需依赖任何外部库。具体实现代码如下：

/**  
 * 调整图片大小  
 * @param imagePath 图片路径，例：D:\Users\AOL\Pictures\test\test_one.jpg  
 * @param outputDir 图片父级地址，例：D:\Users\AOL\Pictures\test  
 * @param width     需要调整的宽度  
 * @param height    需要调整的高度  
 * @return          调整后的图片地址  
 * @throws Exception IO异常及Service异常  
 */  
public static String modifyResolution(  
        String imagePath, String outputDir, Integer width, Integer height) throws Exception {  
    List<String> paths = Splitter.on(".").splitToList(imagePath);  
    String ext = paths.get(paths.size() - 1);  
    if (!Arrays.asList("jpg", "png").contains(ext)) {  
        throw new ServiceException("图片文件格式错误，应该为JPG或PNG类型");  
    }  
    String resultPath =  
            Joiner.on(File.separator).join(Arrays.asList(outputDir, IdUtil.simpleUUID() + "." + ext));  
    //读取原始图片  
    BufferedImage image = ImageIO.read(new FileInputStream(imagePath));  
    log.info("图片文件调整大小,原图:Width={},Height={}，调整为:Width={},Height={}", image.getWidth(), image.getHeight(), width, height);  
    //调整图片大小  
    Image resultingImage = image.getScaledInstance(width, height, Image.SCALE_AREA_AVERAGING);  
    BufferedImage newImage = new BufferedImage(width, height, BufferedImage.TYPE_INT_RGB);  
    newImage.getGraphics().drawImage(resultingImage, 0, 0, null);  
    //图像缓冲区图片保存为图片文件(文件不存在会自动创建文件保存，文件存在会覆盖原文件保存)  
    // 现在是写入到源文件，替换原图  
    boolean flag = ImageIO.write(newImage, ext, new File(resultPath));  
    if (!flag) {  
        throw new ServiceException("图片调整大小失败，请检查图片文件");  
    }  
    return resultPath;  
}

方案优势​

无外部依赖：使用 Java 标准库，无需额外安装任何组件​ 部署简单：避免了因依赖缺失导致的各种问题​ 跨平台性：在所有支持 Java 的平台上都能稳定运行​ 实现简洁：几行代码即可完成核心功能
