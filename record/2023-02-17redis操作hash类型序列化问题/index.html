Redis Hash 类型操作中的序列化问题及解决方案

🚨 问题现象

在使用 Redis Hash 结构的 increment 方法时出现异常：

at io.lettuce.core.ExceptionFactory.createExecutionException(ExceptionFactory.java:135)

观察发现 Redis 中存储的键值都带有特殊前缀：

\xac\xed\x00\x05t\x00\x18...

🔍 问题分析

  1. 序列化冲突：系统默认使用 JDK/JSON 序列化存储数据
  2. 操作限制：increment 操作会直接操作原始值而不会反序列化
  3. 类型不匹配：序列化后的值无法直接转换为数值类型（Integer/Long/Double）

💡 根本原因

当同时存在两种需求时会产生冲突：

  • 需要序列化存储复杂对象
  • 需要对简单值进行原子增减操作

🛠️ 解决方案（代码实现）

方案一：自定义序列化器（推荐） 

public class HybridSerializer extends JsonSerializer<Object> {
    @Override
    public byte[] serialize(Object value) {
        if (value instanceof String) {
            return ((String) value).getBytes(StandardCharsets.UTF_8);
        }
        if (value instanceof Number) {
            return value.toString().getBytes(StandardCharsets.UTF_8);
        }
        // 复杂对象走默认序列化
        return super.serialize(value); 
    }
}

方案二：配置双重序列化策略 

@Configuration
public class RedisConfig {
    
    @Bean
    public RedisTemplate<String, Object> redisTemplate() {
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        // 设置Key的序列化
        template.setKeySerializer(new StringRedisSerializer());
        // 设置Value的序列化策略
        template.setValueSerializer(new GenericJackson2JsonRedisSerializer());
        return template;
    }
}

✅ 最佳实践建议

  1. 键值分离：

    • 复杂对象：使用标准 JSON 序列化
    • 需要原子操作的数值：单独存储为 String 类型

  2. 命名规范：

    user:profile:{uid}    # 存储用户对象
user:score:{uid}      # 存储可增减的积分

  3. 监控建议：

    redis-cli --scan --pattern '*'
